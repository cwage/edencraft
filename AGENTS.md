Project Agent Guide: edenpack

Scope
- This file governs work in this repository. It is the source of truth for how to develop and operate the edenpack modpack generator.

Server target
- EdenMC: https://edenmc.miraheze.org/wiki/Main_Page
- Eden is a civilization-style server with strict rules about client mods. Always cross-check additions against:
  - Rules: https://edenmc.miraheze.org/wiki/Rules
  - Recommended Mods: https://edenmc.miraheze.org/wiki/Recommended_Mods

Versioning
- Minecraft 1.21.11 (variable via `--mc-version`).
- Fabric only — Eden's wiki explicitly recommends Fabric for full mod coverage.

Tooling & Conventions
- Use packwiz to define and export a Modrinth `.mrpack`.
- Entrypoint: `./setup.sh` (idempotent, re-runnable).
- Mod list lives in `mods.yaml`. Pinned versions live in generated `edenpack/mods/*.pw.toml` (regenerated by setup.sh).

Rule-compliance checklist for any new mod
1. Does it grant info a vanilla client wouldn't have (X-ray, entity-through-walls, Y-coord of mobs)? → BANNED.
2. Is it an autoclicker / auto-action (autofish, auto-attack, kill aura)? → BANNED.
3. Is it a bot reading environmental data (block/entity positions for scripts)? → BANNED.
4. Is it a mapping mod with overworld cave-mode enabled by default? → Allowed only if config restricts cave mode to the Nether.
5. Is it cosmetic / HUD / performance / library? → Allowed.
6. Is it on Eden's Recommended Mods page? → Strong signal it's allowed; still verify config.

Operating Rules
- Do not run non-terminating commands in this repo.
- Never use `sudo`.
- Stay within the project directory unless explicitly requested.

Build/Test
- Build/export: `./setup.sh [--upgrade] [--export-mods]`.
- After any version/loader change, re-run `./setup.sh` to regenerate pins and re-export.

Git Workflow
- Never push directly to `main` — use branches and PRs.
- No GitHub remote yet — repo is local-only.
